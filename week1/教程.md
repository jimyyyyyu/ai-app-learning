# 第 1 周教程：从零到第一个 AI 程序

> 学习方式：按顺序一节节来。每节 = 讲解 → 例子 → 练习 → 应用。
> 例子必须亲手敲跑通，练习做完再进下一节。

---

## 第 0 节 地图：AI 应用开发者每天都在干什么

### 讲解
AI 应用开发者**不训练模型**，而是"租用"别人训练好的大模型（DeepSeek、OpenAI 等）。你每天的工作就三件事：

1. **发请求**：把你和用户的对话打包，通过 HTTP 发给大模型
2. **收结果**：模型回你一段 JSON，里面有它生成的文字
3. **装进产品**：把这段文字展示给用户、存起来、喂给下一步

整个 20 周学的东西，全是这三件事的变体和升级。

### 例子
```
你的程序 ──HTTP请求(你的问题)──▶ 大模型服务器
你的程序 ◀─HTTP响应(JSON，含回答)── 大模型服务器
你的程序 ──▶ 终端/网页展示给用户
```

### 练习
合上屏幕，用你自己的话把上面这个流程说一遍（30 秒）。说不出来就再看一眼。

### 应用
第 3 周的流式输出、第 5 周的工具调用、第 10 周的 RAG……全部都是这个流程，只是请求里装的东西更多了。

## 第 1 节 HTTP 与 API：给服务器"打电话"

### 讲解
**API**（应用程序接口）= 两个程序之间对话的规则。你不需要知道 DeepSeek 服务器内部怎么运行，只要按它的规则"打电话"就行。

一次 HTTP 请求就像打电话：

| 打电话 | HTTP 请求 |
|---|---|
| 拨号 | URL（打给谁） |
| 说事 | 请求体（问什么） |
| 报身份 | 请求头（比如带 API Key） |
| 对方应答 | 响应（返回数据） |

### 例子
打开 `week1/free_api_demo.py`，逐行看（这是你第 1 周的第一个文件）：

```python
import requests

URL = "https://api.open-meteo.com/v1/forecast"      # 1. 拨号：天气服务的地址
params = {
    "latitude": 39.9042,                             # 2. 说事：我要北京的
    "longitude": 116.4074,
    "current": "temperature_2m,weather_code",
}
resp = requests.get(URL, params=params, timeout=30)  # 3. 拨出去，等应答
resp.raise_for_status()   # 失败立刻报错
data = resp.json()        # 应答是 JSON，解析成 Python 能用的东西
print(data["current"]["temperature_2m"])             # 取出温度
```

亲手敲一遍（不复制粘贴），然后运行 `python free_api_demo.py`。

### 练习
把经纬度换成你所在的城市（搜索"城市名 经纬度"），跑出你城市的天气。

### 应用
调用大模型也是 `requests.post(...)`——只是 URL 换成 DeepSeek 的地址，参数换成你的对话。第 13 周你做 API 服务，就是反过来：**别人**打电话给你。

## 第 2 节 JSON：程序的"普通话"

### 讲解
两个程序交换数据需要一种通用格式，**JSON** 就是这门普通话。它只有两种零件：

- **对象**（花括号 `{}`）：键值对，像字典
- **数组**（方括号 `[]`）：一串值，像列表

### 例子
天气 API 返回的原始 JSON 长这样（节选）：

```json
{
  "current": {
    "temperature_2m": 14.0,
    "weather_code": 0
  }
}
```

`resp.json()` 把它变成 Python 的字典，然后像剥洋葱一样层层取值：

```python
data["current"]["temperature_2m"]   # 先取 current，再取温度
```

### 练习
在 free_api_demo.py 里加一行，打印 `data["current"]["weather_code"]`，看它等于几（对应"晴/多云"等代码）。

### 应用
大模型 API 的返回**全是 JSON**。第 4 周你还要反过来：逼模型用 JSON 格式回答你。

## 第 3 节 环境变量：把钥匙放在安全的地方

### 讲解
**API Key 就是你的账号密码**。如果写死在代码里：

```python
API_KEY = "sk-abc123..."   # ❌ 危险：代码传到 GitHub，全世界都能看到
```

正确做法：钥匙放在"环境变量"这个口袋里，程序要用时自己掏：

```python
import os
API_KEY = os.environ.get("DEEPSEEK_API_KEY")   # ✅ 从环境里取，代码里没有秘密
```

设置环境变量（PowerShell 里执行）：

```powershell
$env:DEEPSEEK_API_KEY = "sk-你的key"     # 当前窗口有效
setx DEEPSEEK_API_KEY "sk-你的key"       # 永久有效（需重开窗口）
```

### 例子
打开 `week1/hello_ai.py`，看开头 10 行：它就是这么取 key 的。你第 1 周已经用过了。

### 练习
写一个 3 行的脚本 `check_key.py`：从环境变量读 key，打印它的前 6 个字符 + "..."（验证设置成功，又不泄露全文）。提示：字符串切片 `s[:6]`。

### 应用
以后 20 周每个项目都这样存 key。第 15 周 Docker 部署时，环境变量还是唯一的正确姿势。

## 第 4 节 大模型 API 的三个角色：system / user / assistant

### 讲解
你发给模型的不是一句话，而是一个**消息列表（messages）**。列表里每条消息有三种身份：

| 角色 | 比喻 | 谁说的话 |
|---|---|---|
| `system` | 导演 | 你定的规矩和人设，如"你是耐心友好的中文学习助手" |
| `user` | 观众 | 用户说的每一句话 |
| `assistant` | 演员 | 模型之前说过的每一句话 |

**模型没有记忆**。它"记得"上文，是因为你每次都把整个历史重新发一遍。

### 例子
打开 `week1/hello_ai.py`，找到这两行——这就是记忆的全部秘密：

```python
messages = [{"role": "system", "content": "你是一个耐心友好的中文学习助手。"}]
...
messages.append({"role": "user", "content": user_input})      # 你说的，记下来
messages.append({"role": "assistant", "content": reply})      # 它说的，也记下来
```

一次完整请求的 JSON 长这样（这就是发给服务器的"包裹"）：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {"role": "system", "content": "你是中文学习助手"},
    {"role": "user", "content": "什么是 RAG"},
    {"role": "assistant", "content": "RAG 是……"},
    {"role": "user", "content": "它和搜索有什么区别"}
  ],
  "temperature": 0.7
}
```

### 练习
把 system 的人设改成"你是一个只会用文言文回答的老学究"，重跑聊天机器人，感受人设的力量。

### 应用
这就是**所有**对话类 AI 产品的骨架：ChatGPT 是它，客服是它，RAG 也是它（只是往 system 里塞了知识）。

## 第 5 节 两个参数：model 和 temperature

### 讲解

- **model**：用哪个模型。`deepseek-chat` 便宜够用；`deepseek-reasoner` 会深度思考（贵）。
- **temperature**（0 到 2）：**脑洞大小**。
  - `0`：严谨、稳定、每次回答几乎一样 → 适合事实问答、写代码、客服
  - `1` 左右：自然平衡 → 日常聊天
  - 越接近 `2`：越天马行空 → 写小说、想点子

### 例子
让 AI 讲笑话：
- `temperature=0`：每次都讲同一个（可能还不好笑）
- `temperature=1.3`：每次都不一样，偶尔惊艳

### 练习
改 hello_ai.py 的 `temperature`，分别用 `0` 和 `1.3` 让 AI 讲笑话，各试两次，记录差别。

### 应用
第 10 周做知识库问答时，temperature 调 0 附近——客服宁可无趣，不能胡说。

## 第 6 节 多轮对话：让模型"记得"你

### 讲解
第 4 节说了模型无记忆。所谓"多轮对话"，就是**把历史 append 进 messages 再整体重发**。这就是 hello_ai.py 的 while 循环在做的事。

### 例子
运行 hello_ai.py，按这个剧本对话：

```
你：给我推荐三本 AI 入门书
你：第一本适合零基础吗？      ← 没提"书"，模型却能接上
你：我刚才问你的第一个问题是什么？  ← 终极检验
```

### 练习
对话进行到一半输入 `quit` 退出，再重新运行——观察它"失忆"了。这正是第 2 周任务 A 要解决的问题（把记忆存盘）。

### 应用
没有多轮对话，就没有"连续聊天的客服"。第 2 周学 JSON 后立刻给它加存盘功能。

## 第 7 节 本周项目：命令行聊天机器人（整合验收）

### 讲解
本周所有零件你都会了。项目就是把它们组装起来。

### 验收标准（逐条对照你的 hello_ai.py）

## 第 8 节 git 与 GitHub：给代码存档和云备份

### 讲解
三句话人话：

- `git add .` + `git commit -m "说明"` = **存档**（游戏存档点，随时回滚）
- `git push` = 把存档**上传云端**（GitHub）
- 以后每天收工前做一遍，叫"git 三连"

详细命令和报错对照表在 `week1/git速查卡.md`。

### 例子

```powershell
cd "C:\Users\innot\Documents\deepseek-harness\default-workspace\ai-learning"
git add .
git commit -m "week1: 完成聊天机器人"
git push
```

### 练习
把本周成果推上去，然后浏览器打开 `https://github.com/jimyyyyyu/ai-app-learning` 亲眼看到你的代码。

### 应用
GitHub 仓库 = 你的作品集 = 求职时的简历。第 20 周全靠它。
